# Scratch project production checklist

Use this checklist for every remaining School of Code Scratch project.

- [ ] The project has one original, explainable core loop and explicit reset.
- [ ] Student-facing scripts and the finished SB3 share one structured source.
- [ ] The starter includes media, names, positions, variables, and instructions
      but not the completed learning systems.
- [ ] All sprites, backdrops, sounds, and diagrams are original or have a
      recorded, verified reuse licence.
- [ ] Readable source media and suggested costume centres are in the asset pack.
- [ ] The starter, reference, and asset pack are deterministic and reproducible.
- [ ] SB3 ZIP members, `project.json`, asset references, and MD5 filenames pass.
- [ ] Both projects load with the pinned official Scratch VM without exception.
- [ ] Every build section has intention pseudocode, rendered blocks, source
      fallback, a test, a likely mistake, and a teacher checkpoint.
- [ ] Green flag, win restart, loss restart, boundaries, collision priority,
      variables, costumes, visibility, sounds, and repeated runs are tested.
- [ ] Downloads show exact type, byte-derived size, purpose, filename, and MIME.
- [ ] The project page has no CDN dependency, broken internal link, or empty URL.
- [ ] SVG and WAV sources parse; responsive, print, and keyboard behaviour pass.
- [ ] Attribution names the Scratch Foundation and states no affiliation or
      endorsement; no Scratch mascots, logos, or library media are reused.
- [ ] A teacher reviews the checkpoints and parent explanation for plain language.
- [ ] A human opens both files in the graphical Scratch editor and records the
      result before public deployment.
- [ ] Generated caches, `node_modules`, crawl output, and temporary files stay
      out of the commit.
