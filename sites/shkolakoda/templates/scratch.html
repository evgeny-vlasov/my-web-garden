Class structure

A serious lesson can wear a ridiculous costume.

A chase by a giant pigeon is still a lesson in coordinates, random movement, collision detection, score, state, and debugging.

  1. 01
    Meet the ideaSee one concept in a small, understandable example.
  2. 02
    Predict and testSay what the code should do, then run it.
  3. 03
    Build togetherUse the idea inside a guided project with clear checkpoints.
  4. 04
    Change the systemAdd a rule, repair a bug, or make the project behave differently.
  5. 05
    Explain the resultDemonstrate what changed and name the ideas underneath it.

Computer Lab connection

The class gives the idea. The lab gives the idea a life.

In class, a student may build the working core of a game. In the Computer Lab, that same student can add a second level, invent a stranger enemy, tune the difficulty, repair edge cases, or rebuild the controls.

How Computer Lab time works ->
A program is a text. The student is an author.

For parents, a finished game makes learning visible. The student can point to a rule, show a bug, explain a variable, and describe why the latest version works differently from the first.
